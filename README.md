# 老祖法宝模拟器 · 三官天赋与锤、异形态调整

《我要当老祖》的法宝背包摆放工具，支持截图导入、逐件觉醒、长老星级、先后天天赋配置和多线程摆盘。计算与识别均在浏览器内完成，无须登录游戏。

- [在线使用](https://laozu.whk.me/)
- [GitHub Pages](https://hekunwang.github.io/laozu-solver/)
- [源码仓库](https://github.com/hekunwang/laozu-solver) · [更新日志](CHANGELOG.md)

## 使用方法

1. 打开网站，手动添加法宝，或通过「截图导入」识别法宝、觉醒及天赋。识别不清楚的内容可逐项核对和修正，也可选择仅导入法宝。
2. 核对持有数量、每件觉醒等级、对应长老星级、先后天天赋和背包设置。
3. 选择目标与计算时长，点击「开始计算」。可主动停止；得到有效结果后会显示最终摆盘。
4. 使用方案保存与载入保留配置和结果。

截图、识别结果和计算过程均在本机处理，不需要上传图片或连接游戏服务端。工具提供的是法宝属性模型分，不模拟完整战斗，也不保证找到全局最优摆盘。

## 截图识别原理

**法宝盘与觉醒**：通过网格定位，结合属性角标、外观样本、占格形状和共鸣数字匹配法宝；觉醒等级通过右下角数字的字形模板识别，并结合火焰颜色校验。

**先天与后天天赋**：提取天赋标签中的文字，与游戏字体预生成的字形和固定天赋词表匹配，支持已知新旧名称。

识别均在浏览器本地完成，离线资源准备好后也能使用；不确定的结果交由用户核对后导入。

## 离线使用与更新

首次需要联网打开。页面正常显示后，会在后台准备计算、法宝识别、天赋识别和图标等离线资源，无须先运行一次截图识别。

页面标题旁的小圆点表示离线状态：

- **绿色**：当前页面对应的资源已完整缓存，可以离线使用。
- **灰色**：尚未准备完成，或当前浏览环境无法使用离线缓存。

以后使用同一浏览器打开同一地址时：

- **联网打开或刷新**：先检查版本清单。页面版本未变时复用缓存；有新版时加载新版，后台准备新版离线资源。
- **断网或版本检查超过 4 秒**：回退到已完整缓存的版本，仍可导入截图和计算。
- **其他旧标签页仍在运行**：不会阻挡新版启用，也不会主动刷新正在使用的旧页面。

早期缓存版本首次迁移时，若刷新后仍显示旧内容，可等几秒再刷新一次原网址；不需要清理站点数据。已迁移到新版更新机制后，正常刷新即可检查新版。

支持 Service Worker 的现代苹果、安卓和电脑浏览器可使用这套离线机制。「添加到主屏幕」或「安装网站」是可选入口，具体名称由设备和浏览器决定；浏览器自带的「下载网页」或「离线阅读」不等同于本工具的 PWA 离线缓存。清除或被浏览器回收站点数据后，需要联网重新准备。

## 配置与存档

持有清单、收藏、觉醒等级和方案保存在当前浏览器的站点存储中。正式网站、GitHub Pages、本地预览以及不同浏览器之间不会自动同步。

同一站点升级会保留已有配置。旧版存档迁移优先使用已有正式数据，再按有效先遣数据、有效旧正式数据逐类回退；空库存和空列表视为真实选择，不合并库存数量。迁移完成后，主动清空不会再次恢复旧库存；来源数据原样保留，写入失败时不会记录迁移完成。

## 属性计算

长老星级先单独计算倍率；对应属性的天赋、觉醒基础加成、形态或同系光环及邻接百分比合并相加。攻击、防御、生命各自计算，预览与求解使用相同规则。

对单件法宝的任一基础属性，设：

- `B`：法宝原始属性；`s`：对应长老星级的加成比例。
- `t`：该属性的天赋加成；`a`：该件法宝当前觉醒等级的基础属性加成。
- `g`：实际生效、匹配该法宝的形态或同系光环加成之和；`n`：实际触发的邻接属性百分比之和。
- 百分比换算成比例，例如 20% 写作 `0.20`；不适用的加成为 0。

正属性路径保留分阶段取整：

```js
const starBase = Math.floor(B * (1 + s));
const pool = t + a + g + n;
const boosted = Math.fround(
  Math.fround(starBase) * Math.fround(1 + Math.fround(pool))
);
const finalAttribute = Math.trunc(Math.fround(boosted + 0.5));
```

长老星级加成仅对有对应配置的红色法宝生效；按该法宝配置读取不超过所选星级的最高档，普通法宝不受影响，不同长老的加成档位可能不同。

例如「燧火传薪」原始攻击 93，长老 4 星加成 100%，觉醒 2 的基础加成 20%，且无其他加成时，先算 `floor(93 × 2) = 186`，再算 `186 × 1.2` 并按上述规则取整，得到攻击 **223**；同条件防御为 **31**、生命为 **12720**。

伤害、暴击增伤等独立通道不并入攻防血加成池。觉醒技能列表升级采用完整替换，避免旧、新技能重复叠加。配置核对不等同于游戏实战结算验证。

## 本地运行与构建

网页运行和构建使用已有 Node.js 环境，不需要安装第三方依赖或本机 OCR 服务。在仓库目录执行：

```sh
node build.cjs
LAOZU_PORT=18778 node serve-web.cjs
```

然后访问 <http://127.0.0.1:18778/>。服务只监听本机；手机上的 `127.0.0.1` 指向手机本身。

完整网页产物位于 `web/`。当前网页使用外部脚本、样式和 Worker，请通过网站或本地服务打开，不使用双击 HTML 的方式验收 PWA。正式托管需要 HTTPS，本机 `localhost` 或 `127.0.0.1` 可用于离线开发验证。

构建会在仓库根目录生成调试用的 `index.html` 和 `app.js`。发布时使用 `web/`，并将相同产物同步到仓库根目录，以供 GitHub Pages 使用；根目录调试页不能代替 `web/index.html` 发布。构建前的 `web/` 会保留为 `.web-previous-*`。

已有检查可分别运行：

```sh
node tests/public-web-build.cjs
node tests/offline-cache.cjs
node tests/official-storage.cjs
node tests/formal-talent-scoring.cjs
```

## 源码与数据维护

原仓库提供单文件构建产物，没有原始前端工程。本仓库保留 `upstream.html` 和 `upstream-bundle.js`，通过可重复执行的补丁继续维护；补丁锚点不匹配时会报错。

| 文件 | 用途 |
| --- | --- |
| `build.cjs`、`patch-upstream.cjs` | 应用补丁并生成网页 |
| `web-build.cjs` | 打包带内容指纹的静态资源 |
| `offline-support.cjs`、`offline-client.js` | PWA 缓存、版本检查与离线状态 |
| `patch-instance-engine.cjs`、`patch-instance-ui.cjs` | 逐件觉醒及保存、显示 |
| `patch-solver-*.cjs`、`patch-active-aura.cjs` | 摆盘搜索与属性计算 |
| `awakening-recognizer.js`、`patch-recognition-*.cjs` | 法宝与觉醒截图识别 |
| `talent-lite-*.js`、`talent-picker.cjs` | 固定词表天赋识别与选择 |
| `build-catalog.py`、`catalog_sync.py` | 配置目录生成与同步 |
| `data/manifest.json`、`data/export-manifest.json` | 配置来源、版本与校验信息 |

仓库包含重建网页所需的解码配置表及字形数据。日常构建直接使用已有数据；更新配置表时才需要相应的 Python 环境和配置解码流程。原始游戏资源导出工具不随仓库提供。

新增法宝或机制时，需要同步目录、形状、识别样本与计算模型，不能只改版本号。`data/prerelease/` 保留历史来源记录，当前法宝和觉醒配置以正式服快照为准；后天天赋名称使用前述单独标明的来源。
